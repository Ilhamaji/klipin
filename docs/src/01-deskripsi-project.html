1. Ringkasan Eksekutif

Klipin adalah aplikasi web yang membantu pendidik, mahasiswa, dan peneliti menemukan literatur akademik, mengklasifikasikannya ke mata pelajaran dan jenjang sekolah, lalu meringkas isi PDF artikel menjadi materi ajar terstruktur dalam Bahasa Indonesia.

Sistem terdiri dari tiga layanan yang berjalan terpisah namun terhubung melalui HTTP: frontend Next.js sebagai antarmuka, backend Express sebagai gateway autentikasi dan data, serta AI service FastAPI yang menangani pencarian, klasifikasi, ekstraksi PDF, dan pemanggilan LLM. Database PostgreSQL dipakai bersama oleh backend dan AI service.

Nilai utama system terletak pada dua pipeline. Pipeline pertama mengubah kata kunci menjadi lima artikel relevan yang sudah dilabeli mapel dan jenjang, dengan cache semantik agar query serupa tidak memanggil API pencarian lagi. Pipeline kedua mengubah URL artikel menjadi ringkasan tujuh bagian, dengan toleransi terhadap berbagai bentuk halaman jurnal (PDF langsung, OJS, dan halaman HTML).

2. Latar Belakang dan Tujuan

Masalah

  • Pencarian literature tersebar. Pendidik harus membuka Google Scholar, membuka tiap hasil, lalu menilai sendiri relevansinya.
  • Klasifikasi manual. Menentukan sebuah artikel masuk mapel dan jenjang mana membutuhkan waktu dan konsistensi tinggi, terutama untuk 45 kombinasi mapel–jenjang.
  • Ringkasan tidak seragam. Setiap artikel punya struktur berbeda; merangkum manual menghasilkan format yang tidak konsisten.
  • Tidak ada repositori pribadi. Hasil pencarian dan ringkasan mudah hilang karena tidak tersimpan per pengguna.

Tujuan

  1. Menyediakan satu alur kerja: cari → lihat klasifikasi → ringkas → simpan.
  2. Mengotomasi klasifikasi artikel ke 45 kelas Kurikulum Merdeka dengan model yang dapat dibandingkan.
  3. Menghasilkan ringkasan terstruktur tujuh bagian dalam Bahasa Indonesia dari PDF berbahasa apa pun.
  4. Menyimpan histori pencarian, catatan, dan library per pengguna dengan autentikasi JWT.
  5. Menjaga biaya operasional: cache query dan cache ringkasan mengurangi panggilan API berbayar.

6. Pipeline Pencarian dan Klasifikasi

Alur lengkap saat pengguna menekan tombol cari:

Frontend mengirim POST /api/search dengan body { query } dan header Authorization: Bearer <JWT>.
Backend memverifikasi JWT, memastikan user ada, lalu memanggil POST /ai/search di AI service dengan { query, user_id }.
AI service mengubah query menjadi embedding LaBSE 768 dimensi.
Cache semantik: dicari query milik user yang sama dengan cosine similarity ≥ SIMILARITY_THRESHOLD (default 0,85). Jika ada, artikel lama langsung dikembalikan dengan source: "cache".
SerpAPI Google Scholar dipanggil (default 10 hasil, hl=id). Hasil berbentuk buku/ISBN dibuang.
Semantic re-ranking: setiap hasil di-embed dari gabungan judul + abstrak, lalu diurutkan berdasarkan cosine similarity terhadap query. Diambil 5 teratas.
Klasifikasi: teks judul + abstrak (maksimal 1500 karakter) dibersihkan dengan preservation_clean(), di-embed, lalu diprediksi oleh 4 model. Label dengan confidence tertinggi menjadi subject dan jenjang artikel.
Persistensi: query, embedding, model_comparison, dan artikel disimpan ke PostgreSQL. Backend mengembalikan artikel lengkap dengan id database yang dipakai untuk simpan ke library.

Detail teknis yang perlu diketahui

ParameterDefaultDampak
SIMILARITY_THRESHOLD0,85Ambang cache. Terlalu rendah: hasil lama dipakai untuk query yang sebenarnya berbeda. Terlalu tinggi: cache jarang kena.
SERPAPI_NUM10Jumlah hasil mentah dari Google Scholar.
SERPAPI_TOP_K5Jumlah artikel yang dikembalikan ke pengguna setelah re-ranking.
MAX_BODY_WORDS1000Batas kata naskah yang dikirim ke LLM (bukan untuk pencarian).
Batas teks klasifikasi1500 karakterHardcoded di classify(); mencegah input sangat panjang memperlambat inferensi.

Cache bersifat per pengguna. find_most_similar_query() memfilter user_id, sehingga riwayat pencarian satu pengguna tidak bocor ke pengguna lain meskipun query-nya identik.

Mode perbandingan model

Selain memilih label terbaik, AI service mengembalikan model_comparison: hasil keempat algoritma pada query yang sama (label, confidence, status accepted/rejected). Data ini disimpan sebagai kolom JSON di tabel queries dan dapat ditampilkan sebagai pembanding di UI. Sebelumnya field ini dibuang oleh Pydantic karena tidak dideklarasikan, dan sudah diperbaiki di schemas.py.

8. Pipeline Ringkasan PDF

Ringkasan dipicu saat pengguna memilih artikel, lalu frontend memanggil POST /api/summarize dengan { url }.

Cache ringkasan: URL di-hash SHA-256; jika hasil masih ada dan belum kedaluwarsa (default 24 jam), hasil dikembalikan tanpa memanggil LLM.
Resolusi PDF (_find_pdf_url): coba pola OJS /article/view/ → /article/download/; jika URL langsung PDF, pakai; jika HTML, cari a.pdf atau link yang mengandung .pdf, /pdf, download, fulltext.
Validasi: respons harus application/pdf; jika tidak, permintaan gagal dengan 422.
Ekstraksi PyMuPDF: seluruh halaman dibaca, judul diambil dari metadata PDF lalu fallback ke blok teks terbesar di bagian atas halaman pertama.
Pemisahan pustaka: teks dipecah pada kata daftar pustaka, references, bibliography. Naskah utama dibatasi 1000 kata, pustaka 200 kata.
LLM: Groq openai/gpt-oss-20b, temperature 0,2, reasoning_effort: low, maksimal 1300 token output. Retry otomatis saat 429/5xx.
Parsing: output dipecah menjadi 7 field dengan regex. Jika field kurang dari 4 atau output terpotong, permintaan diulang.
Simpan cache lalu kembalikan ke frontend untuk ditampilkan dan dapat disimpan sebagai catatan.

Kontrak output ringkasan

FieldIsi
judulJudul dokumen; fallback dari metadata/first page jika model mengosongkan

kompetensiFokus masalah, tujuan, atau kompetensi

daftar_pustakaReferensi utama dari dokumen

Batasan yang melekat

  • Paywall dan JavaScript. Halaman yang membutuhkan login atau merender PDF via JavaScript tidak bisa diambil dengan requests.
  • PDF hasil scan. PyMuPDF tidak melakukan OCR; dokumen scan tanpa layer teks akan menghasilkan teks kosong.
  • Kuota LLM. Free tier Groq dibatasi token per menit; dokumen sangat panjang akan terpotong sesuai SUMMARY_MAX_*.
  • Konsistensi format. Model dapat mengembalikan variasi label; parser sudah toleran, tetapi prompt yang diubah harus menjaga tujuh label tersebut.

9. Skema Database

TabelKolom utamaFungsi

Relasi

users 1 ────── N notes users 1 ────── N queries 1 ────── N articles users 1 ────── N saved_articles N ────── 1 articles

Semua foreign key memakai ON DELETE CASCADE kecuali yang tidak relevan, sehingga menghapus user akan membersihkan catatan, query, artikel, dan library-nya. Unik gabungan pada saved_articles mencegah artikel yang sama disimpan dua kali; backend memetakan pelanggaran ini menjadi HTTP 409.

Catatan operasional

  • Backend tidak membuat tabel otomatis. Jalankan database/schema.sql sebelum start.
  • AI service menjalankan migrasi ringan saat startup: ALTER TABLE queries ADD COLUMN IF NOT EXISTS model_comparison JSON.
  • Kolom embedding disimpan sebagai JSON, bukan tipe vektor. Pencarian kemiripan dilakukan di aplikasi (Python), bukan di database.
  • Supabase pooler memakai port 6543 dan SSL; PostgreSQL lokal memakai 5432 tanpa SSL (DB_SSL=false).

Konsekuensi Netlify Functions

Fungsi sinkron Netlify memiliki batas sekitar 10 detik. Karena itu backend memakai AI_TIMEOUT_MS=9000 untuk pencarian agar kegagalan muncul sebagai pesan yang bisa dibaca, bukan timeout platform yang tampak seperti error CORS. Untuk ringkasan, AI_SUMMARIZE_TIMEOUT_MS dinaikkan ke 55 detik dan membutuhkan platform yang mengizinkan durasi tersebut.

Cold start

Space gratis tidur saat tidak dipakai. Permintaan pertama membutuhkan puluhan detik, sehingga backend mengembalikan 503 AI_WARMING_UP. Frontend memanggil /api/ai/ready lebih dulu untuk memanaskan layanan. Untuk produksi, pertimbangkan Space berbayar atau container yang selalu hidup.

Rekomendasi pengembangan

  1. Umpan balik pengguna. Simpan koreksi label agar model dapat dievaluasi ulang dan dataset bertambah.
  2. Plugin sumber data. Abstraksi provider pencarian dengan antarmuka seragam (lihat dokumen tutorial).
  3. Antrian ringkasan. Pindahkan proses PDF+LLM ke job queue agar request HTTP tidak menunggu lama.
  4. Observability. Catat durasi per tahap (SerpAPI, embedding, klasifikasi, LLM) dan tingkat kegagalan.
  5. Keamanan produksi. CORS terbatas, rate limit, autentikasi internal untuk AI service, dan rotasi secret berkala.
